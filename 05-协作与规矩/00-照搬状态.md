## 五、没搬的为什么没搬（别下次又捡起来）

- **计划任务**：需要 Xiodra 开权限。已写进 `协作规矩.md` 的「待 Xiodra 确认」。
- **通知看板 / 超级通道**：参照那套要"影响面标签 → 面板映射表"，我们只有 2 个场景、3 个面板，映射表比收益大。要时再加。
- **帮手会话名册**：我们没开过帮手；开了再照抄 §四.1 那张表。
- **413 / 上下文压力 / 模型窗口**：属引擎侧，改了上游同步会丢（这是本场景铁律：不碰 `引擎\`）。
- **清理/设计/顾问团归口**：没有对应场景，照抄只会是死代码。
- **整树部署**：我们不做部署。

## 六、给"规矩"加一条时照这个顺序（抄参照五步，落成命令）

```
第 1 步  写清「违规长什么样」        → 能写成条件（"地盘表多一行没对应场景"，不是"要一致"）
第 2 步  找到唯一的判据出处          → 一个工具 / 一节，⛔ 别两处各判一次
第 3 步  写一个能 exit 非 0 的检查    → 输出点名的差异集合
第 4 步  给它一个"应当失败的反例"     → 造违规 ⇒ 必须报 ⇒ 恢复（不报 = 假检查）
第 5 步  挂到节奏上                  → 加进 `机制体检.mjs` 的 ITEMS；最好再挂计划任务（要 Xiodra 拍板）
```
