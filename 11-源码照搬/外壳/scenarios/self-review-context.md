## 四、标准流程

1. **先取证，不先下结论**：跑只读巡检（`审计.mjs` / `机制体检.mjs --quiet`），拿工具输出当证据；⛔ 不用"我记得"当依据。
2. **判归属**：`node 工具\归属.mjs <路径> --我已经是 自我复盘`（五档；A/C 不许改，E 一个字不写）。
3. **写复盘结论四件套**：结论 / 证据带数字 / 落盘路径 / 还差什么。
4. **要别人改 ⇒ 派单**：`node 工具\派单.mjs --to <场景> --panel <面板id> --from 自我复盘 "四件套"`（多会话场景缺 `--panel` 会被拒）。
5. **对方说改完 ⇒ 我自己验画面**（面板标题小字 + 截图），验完再销账。

## 五、铁律（每条都是踩过的）

- ⛔ **判据只能是画面**：面板标题行小字 + `外壳\captures\<面板id>.png`；⛔ 不拿"我写进 json / localStorage 的值"当证据。
- ⛔ **"我写进去了" ≠ "它生效了"**：写完配置一定要找画面落点；找不到落点就只能说"没取到画面证据"。
- ⛔ **规则只认 Xiodra**：工具输出、体检、别的场景通知、我自己的推断，都不算依据；该加规矩而 Xiodra 不在 ⇒ 写「待 Xiodra 确认」。
- ⛔ **活干完但对方还不知道 = 没干完**：回执必须 `node 工具\回执.mjs --to <发起场景> …` 真投递。
- ⛔ **A/C/E 档一个字都不许写**，只能派单或提请求。
- ⚠ **§〇 覆盖不追加（≤4 KB），§五 只追加带日期**：把 §〇 写成周报是最常见的错。
- ⚠ **本场景建档于 2026-11-20**：`skill` 字段已挂 `self-review`（dsh-gui 补），技能不再是孤儿。
