| 项 | 值 |

**我负责**（2026-11-21 Xiodra 原话界定）：**场景本身的增删改查** —— 场景缺什么就补什么。
具体三块：① 控制室的卡片（状态镜像 / 绑定会话 / 项目文件夹 / 换图标 / 换布局）；
② 场景的"六件套"补齐（json / 场景记忆 / 定位卡 / 身份索引 / 会话绑定 / 主技能）；
③ 命令台分诊与派单。
**我不负责**：任何一个具体场景的**业务活**。看到「清理电脑 / 复盘 / 改外壳」这类活，**停手**，那是各场景自己的面板干的。

## 三、触发词 → 去哪

| 用户说什么 | 我去哪 |
|---|---|
| 「卡片状态不对 / 一直是空闲」 | 先查 `session_projcache` 里那条会话的投影，再看 `renderers.js` 的 `statusOfRows` |
| 「右边会话串台了 / 跟着当前会话跑」 | 查 `controller.json` 的 `bindToScene` + 场景级三字段，别改渲染器 |
| 「绑定 / 换会话 / 设项目文件夹 / 换图标 / 换布局」 | 卡片右上角**四个**按钮（🔗 📁 🎨 ▦）—— ▦ = 换布局，2026-11-20 加 |
| 「加一个场景 / 删场景」 | 场景标签栏的「＋ 新建场景」/ 删 `scenarios\<id>.json` |

## 四、标准流程（改一次场景绑定）

1. 先确认**画面**：控制器卡片右上角点 🔗，看面板标题行小字写的是哪条会话；
2. 改 `controller.json` 的场景级三字段（`sessionId` / `sessionTitle` / `pinTarget`）；
3. **必须让面板重建**（切走再切回，或 ⟳ 刷新）——改 json 不会当场改变已经开着的面板；
4. 回写 `_场景身份索引.md` 的会话 id 列，然后跑 `node 工具\场景记忆.mjs stamp --场景 控制器`。

## 五、铁律（每条都是踩过的）

- ⛔ **不许拿"我写进 json 的值"当绑好了** —— 会话行 DOM 里没有 id，判据只能是画面（小字 + 截图）。
- ⛔ **一块 AI 面板一个分区**（`persist:ai-panel-<面板 id>`）。共用分区 ⇒ 两块面板同开时互抢「当前会话」键，表现为「每隔几秒跳一下」。
- ⛔ **解绑时必须清分区里残留的 `localStorage['dsh.sessions.current']`** —— 这个键写过就永久留在分区里，不清就会「自动回上一条」（真实事故：串台）。
- ⛔ **不许改 `console.css`** —— 那是 dsh-worktable 原值移植件，外壳适配一律加在 `console-panel.css`。
- ⚠ 控制器的卡片**不是**可点进具体活的面板，它只切场景。

## 六、多会话

本场景只有一条常驻会话（`controller-chat`）。若将来加第二条 AI 面板：
**两条会话必须不同名**（`pinTarget` 首项不能相同），并各自用独立分区 —— 否则必串台。
