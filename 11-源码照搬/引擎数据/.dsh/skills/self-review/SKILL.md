# 自我复盘

## 一、开场（30 秒）

1. 读 `引擎数据\.dsh\场景记忆\自我复盘\场景私有记忆.md` 的 `## 核心职责`（≤10 行）。
2. 读 `外壳\scenarios\self-review-context.md`（定位卡：资产地图 / 铁律）。
3. 读 `引擎数据\.dsh\skills\_索引.md` —— ⛔ 别全量读技能，先看索引。

## 二、M10 五步输出模板（照抄这个结构，别自由发挥）

对**每个**要复盘的项目，按下面五项逐个写：

| # | 输出 | 判据 |
|---|---|---|
| ① | **新增可复用技能**（含索引关键词） | 这条经验下次还会用到吗？会 ⇒ 写成技能并登记索引 |
| ② | **定位卡是否需更新** | 资产地图 / 触发词 / 铁律 有没有变？变了就说改哪一行 |
| ③ | **核心写回 vs 垃圾沉淀原始层清单** | 核心 = 每天上班必须知道（≤10 行）；其余进 `原始层\` |
| ④ | **可固化为脚本的重复劳动** | 同一套命令第 3 次手打 ⇒ 该写成 `.mjs` |
| ⑤ | **更新后的交接摘要**（≤200 字） | 换会话时新 AI 读完能立刻接上 |

## 三、硬判据

- ⛔ **不写"感觉":每条结论都要能指向文件或命令输出**（带数字）。
- ⛔ **不动别人的地盘**：`外壳\renderer\` / `主进程` 是 C 档，只能派单。
- ⛔ **不自己加规矩**：该加但 Xiodra 不在 ⇒ 写进 `_共享记忆\冲突.md` 待他拍板。

## 四、收尾

1. 结论写回本场景 `## 核心职责`（覆盖，≤10 行）；历史进 `原始层\`。
2. 发现别场景的问题 ⇒ 派单：`node 工具\派单.mjs --to <场景> --panel <面板id> "四件套"`。
3. 重复劳动要固化 ⇒ 列进「固化建议」并说明"什么时候跑哪个脚本"。
