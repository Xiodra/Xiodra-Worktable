  但**没挡场景记忆**（`git check-ignore` 对 `场景私有记忆.md` 返回 exit=1）。

- **2026-11-23 · 远端通道 —— 本条曾写错，已更正**：
  ✅ **SSH 是可用的**：`git ls-remote origin` exit=0（读到 HEAD + refs/heads/main 两行，均 `e3f9284`）；
  `ssh -o BatchMode=yes -p 443 git@ssh.github.com` 回 `Hi Xiodra! You've successfully authenticated`。
  走的代理是 `~/.ssh/config` 的 `ProxyCommand connect -S 127.0.0.1:10808 %h %p`，
  `connect.exe` 实际在 `C:\Program Files\Git\ucrt64\bin\connect.exe`（87,617 B，**不在 PATH 上但 ssh 找得到**）。
  ⛔ **先前那条"SSH 不可用 / 唯一通道 https:443"错在两处**：
  ① `couldn't create signal pipe, Win32 error 5` 是**沙箱受限模式的症状**（受限模式不让进程开命名管道），
     不是这台机器的真实限制 —— 切成 full-access 后同一条命令 exit=0；
  ② 我当时只查了 3 个路径就断言 `connect.exe` "不存在"，实际它在 `ucrt64\bin\` 下。
  **教训：工具报错先分清"环境限制"与"机器事实"，别把沙箱症状写进永久记忆** ——
  那会让下一任 AI 永远绕开一条其实能走的路。复验命令：`git ls-remote origin`（exit=0 即通）。
  仍然为真的一条：全局 `url.https://kgithub.com/.insteadof` 把 https 改写到已连不上的镜像，
  所以走 https 需用 `https://github.com:443` 绕开改写。
