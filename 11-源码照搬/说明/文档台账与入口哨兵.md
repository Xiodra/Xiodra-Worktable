> 补缺清单的最后三项缺口。前两项来自《05-协作与规矩》与《04-工作台搭建》，第三项是参照三起事故的直接抓手。

## 一、文档台账 `工具\文档台账.mjs`

**判据出处**：《05/二-标准化规范》§2.7（索引机制）+ §2.10（文档生命周期）

| 判据 | 值 |
|---|---|
| 文档密集 | 直接子文档 **≥30**，或 **≥8 且 ≥500 KB** |
| 四状态 | `活`（每次读写）/ `常备`（180 天复核）/ `留档`（只作证据）/ `待清`（7 天内必须处理） |
| ⛔ 状态格只许四词 | 写成「留档（2026-10-18 归档）」会被体检认不出 ⇒ 当成未登记 |

**我们的实测结论（诚实版）**：扫了工作台根下 18 个有文档的目录，**没有一个达到密集判据**
（最多 8 份 / 208 KB）。所以**不建强制索引** —— 参照那边 85 KB 的全机台账，对我们是过度设计。

这个工具的价值在「能查」而不是「现在有东西要查」：哪天某个目录涨到 30 份，`--check` 会立刻 ⛔。

```powershell
node 工具\文档台账.mjs --scan     # 18 个目录各多少份、是否密集、有无索引
node 工具\文档台账.mjs --check    # 密集无索引 ⇒ ⛔；状态词非法 / 到期 ⇒ ⛔
```

## 二、入口哨兵 `工具\入口哨兵.mjs`

**判据出处**：《04/事故复盘-三起》事故一「改了一个 exe 的版本信息，整个工作台变灰白」

### ⛔ 为什么不能照抄参照的判据

| | 参照 | 我们 |
|---|---|---|
| 入口 | `启动器\工作台.exe`（打包产物） | `启动.vbs` → `工具\启动配置.vbs` → `electron.exe`（node_modules 里） |
| 联接 | `resources\app` 目录联接 → 源码 | 无（直接跑源码） |
| 抓手 | exe 哈希 + 联接是否还在 | **四个可坏点，见下** |

### 我们的四个可坏点（唯一出处）

| # | 查什么 | 坏了会怎样 |
|---|---|---|
| ① | `启动.vbs` / `外壳\start.vbs` 存在且 **ANSI(GBK) 无 BOM** | 存成 UTF-8 ⇒ 中文路径读成乱码，双击没反应 |
| ② | `工具\启动配置.vbs` 存在，且两个启动器**引用路径一致** | 少了 / 搬了没改引用 ⇒ `MsgBox 缺少 工具\启动配置.vbs` 然后退出 |
| ③ | `config.json` 能解析，四个路径键**都 `Test-Path` 指得到** | "长得对"≠"指得对"（我们踩过 CInt 端口坑） |
| ④ | `electron.exe` 存在 + **指纹与基线一致** | `npm install` 升级 / 手工替换 ⇒ 指纹变 |

```powershell
node 工具\入口哨兵.mjs            # 查（⛔ ⇒ exit 1）
node 工具\入口哨兵.mjs --save     # 记 electron.exe 指纹基线（npm install 后重记）
```

## 三、日志看门 `工具\日志看门.mjs`

**判据出处**：《04/自检清单》§3「面板变白时的排查顺序（别跳步）」

```
1. server.log 找 launch-failed → 有 ⇒ 壳的问题
2. 确认 exe 是原来那个（哈希）  → 变了 ⇒ 别改名/别替换，请机主重启
3. 面板重载（all）             → 好了 ⇒ 只是渲染层没刷新
4. 控制台看单个面板的报错       → 有 ⇒ 该面板渲染器的问题
5. 最后才请机主重启工作台
> ⛔ 顺序颠倒的代价：先重启了，证据就没了，下次还会再犯。
```

本工具只能自动做第 1 步（读日志），第 2 步交给 `入口哨兵.mjs`，第 3 步交给 `刷新面板.mjs`。
所以它的输出**按那五步的顺序给建议**，而不是只丢一堆错误。

### 一个必须记住的判据

> **旧证据 ≠ 新故障。**

第一版对整个日志文件匹配 ⇒ 只要历史上失败过一次，之后每次都报 ⛔。
实测：`server.log` 第 48 行有旧的 `[server exited] code=1`，但后面明明
`engine ready in 22.2s` + 两个面板 `status=200` —— 现在完全是好的。

修法：先找**最后一次启动成功**的标记，只扫它**之后**的日志。
判据反过来也成立：启动成功之后又 `server exited` ⇒ 必须报。
