# 自动归档 & 验证闸（照搬《13-公开情报/单场景自我进化-最小闭环》）

> 参照项目把这两个留白给"成品版"，理由是「**速度与保险才是护城河**」。
> 我们这边自己做出来了 —— 因为这两件恰好是"越用越稳"和"不会悄悄坏"的唯一手段。

---

## 一、验证闸 `工具\验证闸.mjs`

**治什么**：改完一堆东西，看着都绿，其实某处已经悄悄退化（掉了一项检查、坏了一个绑定）。

参照的原话：「**硬判据 + 反例清单 + 检查脚本，保证改完不会悄悄退化。没有它，写得越多越可能坏。**」

### 三件缺一不可

| # | 做什么 | 判据 |
|---|---|---|
| ① **硬判据** | 跑全部体检（机制/协作/索引/场景六件套/记忆/MCP） | 任一 ⛔ ⇒ **闸门关闭**，exit 1 |
| ② **基线比对** | 和上次通过的状态比，输出**差异集合** | 必须能说出「**哪一项**从通过变成不通过」，⛔ 只给 0/1 没用 |
| ③ **反例自证** | 故意造一个必失败项 | 闸门**必须真的关**。反例不关 = 这个闸是装饰 |

### 一条关键判据（我们加的）

> **闸门关着时绝不更新基线。**

否则下次比对的对象就变成"已经坏掉的状态"，真正的退化再也比不出来 —— 等于把闸门永久打开。
（实测：先造退化 → 闸门关 → 再跑一次仍报退化，证明基线没被污染。）

### 怎么用

```powershell
node 工具\验证闸.mjs              # 跑 → 与基线比 → 落基线（只在全绿时落）
node 工具\验证闸.mjs --selftest   # 反例自证（PASS 3/3）
node 工具\验证闸.mjs --diff       # 只看盯着的文件哪些动了
node 工具\验证闸.mjs --strict     # ⚠ 也算关
```

**时机**：改完任何会影响工作台的东西之后、换版本之前、真跑一次大改之前。
基线在 `引擎数据\.dsh\场景记忆\_共享记忆\_验证闸\基线.json`，历史在 `历史.jsonl`（只追加）。

## 二、自动归档 `工具\自动归档.mjs`

**治什么**：记忆越写越长，主文件超 25 KB 红线就会挤掉开场必读的 §〇；手工搬又总忘。

参照的原话（图1）：「会话 ──当前交接──▶ **归档备份（历史会话 / 旧版记忆，只进不改）**」，判据是"**可回滚；不为了'干净'删证据**"。

### 四条机械判据（⛔ 不按日期搬）

| # | 判据 | 为什么 |
|---|---|---|
| ① **超体量才搬** | 主文件 > 25 KB（`--max-kb`） | 没超就一节都不动，**不为了"干净"删证据** |
| ② **挑最大的搬** | 按字节从大到小，够降到线下就停 | 按日期搬会误伤"今天写的关键决策"（我们今天的记忆全是今天的） |
| ③ **保护区永不搬** | `§〇` 四小节 / `## 核心职责` / `### 5) 全貌` / `§一 §二` | 它们是新会话开场必读的导航，搬走 = 失忆 |
| ④ **已是指针不再搬** | 标题带 `→ \`归档\…\`` | 否则归档会重复堆两份 |

### 两条安全的保证

- **只搬不丢**：搬完逐行核对「原文每个非空行都在归档文件里」，**缺一行就自动回滚主文件**。
- **指针带触发句**：原位置留的不是一行路径，而是
  `要 查「<那件事>」的经过与取证 时，读 归档\§五-自动归档-<日期>.md`。
  ⛔ 只留路径 = 等于没写（人和 AI 都会跳过）。

### 怎么用

```powershell
node 工具\自动归档.mjs                    # dry-run：只列会搬什么
node 工具\自动归档.mjs --go               # 真搬（先备份主文件，核对通过才删备份）
node 工具\自动归档.mjs --场景 DSH·GUI --go
node 工具\自动归档.mjs --selftest         # 反例自证（PASS 6/6）
```

**实测**：给控制器记忆塞到 49 KB → 只挑中那个 42.7 KB 的大节、§〇 一节没动 → 搬完 7.4 KB、缺 0 行。测试数据已还原。

## 三、它俩怎么配合（这才是闭环）

```
改东西 ──▶ 自动归档（记忆超线了就把旧正文搬走，留触发句指针）
              │
              ▼
          验证闸（硬判据 + 与基线比 + 反例自证）
              │
      ┌───────┴────────┐
   闸门开            闸门关
      │                 │
  落基线，继续      列差异，⛔ 不落基线
```

- **自动归档管"写多了会不会挤掉导航"**；**验证闸管"改多了会不会悄悄坏"**。
- 两个都进了 `机制体检.mjs`（15 项），所以一条命令能看全貌。
- 两个都有 `--selftest`，所以它们自己也在被验。

## 四、和参照的差别（诚实版）

| 参照 | 我们 | 说明 |
|---|---|---|
| 自动**归纳**（从对话提候选写回，人审并入） | **没做** | 需要模型侧参与 + 人工审核流；我们先用"写回判据"约束人写 |
| 验证闸 | 做了，并按我们自己的体检重写 | 参照没给判据与脚本，我们是照"三件"的要求自己实现 |
| 自动归档 | 做了 | 参照把"归档"列为能跑的三件事之一（手工工具），我们补上"自动判线+自动搬+自动核对" |
| 私有技能自动进化 | **没做** | 同上，需要"哪条技能该更新"的判断，不属于机械判据 |
