## 一、一条命令看全貌

```powershell
node 工具\机制体检.mjs            # 7 项全跑，任一 ⛔ 就 exit 1，并自动进待办
node 工具\机制体检.mjs --selftest # 反例门禁：6 个自造违规，确认每项真的会报
```

`--selftest` 是这套东西的**命门**：反例不报 ⇒ 那个检查是假的（原文第 4 步，90% 的人会漏）。

## 三、"例 2" 的两条去向（别只写一条）

原文例 2 只说"进待办"。我们做了**两条**，因为只看一行字的人会问"那谁修？"：

| 去向 | 文件 | 谁看 |
|---|---|---|
| 待办板 | `引擎数据\.dsh\场景记忆\_共享记忆\_待办.md` 的 `## 体检 ⛔` / `## 机制体检 ⛔` 段 | AI 每轮开场注入时第一眼看到 |
| **分诊表** | `工具\_体检待办.md`（场景 → 面板 → 会话 → 定位卡 → 一条修复命令） | 人一眼看出"该谁的活" |

⛔ 待办板只写**指针**（≥8 条截断），不复制问题正文 —— 否则板子自己会变成第二份报告。

## 五、新加一条机制时照这个顺序做（抄原文五步，落成命令）

```
第 1 步  写清「违规长什么样」        → 必须能写成条件（"存在但没登记"，不是"不完整"）
第 2 步  找到唯一的判据出处          → 一个工具 / 一节规范，⛔ 别两处各判一次
第 3 步  写一个能 exit 非 0 的检查    → 输出差异集合（"⛔ 3 项：…"）
第 4 步  给它一个"应当失败的反例"     → 造违规样本 ⇒ 必须报 ⇒ 恢复（不报 = 假检查）
第 5 步  挂到节奏上                  → 进 `机制体检.mjs` 的 ITEMS，最好再挂计划任务
```

第 5 步在我们这里的落法：**把那一项加进 `工具\机制体检.mjs` 的 `ITEMS` 数组**，
并在它的 `--selftest` 里补一个反例。这样"新机制"自动继承"一条命令看全貌"。
